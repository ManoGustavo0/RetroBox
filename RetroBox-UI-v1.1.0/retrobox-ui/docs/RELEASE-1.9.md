# RetroBox 1.9.0 · Relatório da atualização

Esta versão preserva o arquivo raw independente, o caminho histórico, a API tradicional, as doze paletas e o esquema dos perfis. As verificações de lógica não equivalem a uma execução em Roblox/Unbound real.

| Item | Resultado |
| --- | --- |
| 1. Causa da Command Palette | O host da lista interna não definia `_visible`. O guard do botão interpretava a seção como oculta e bloqueava Activated. Os testes antigos chamavam Choose diretamente, sem percorrer esse guard. Além disso, alvos de abas dependiam de índices mutáveis e o foco/scroll não aguardava o layout. |
| 2. Correções | Host visível, z-order das linhas novas/recicladas, caminho real de clique/toque/Enter, referências capturadas para abas, rejeição de controles removidos/ocultos, scroll/foco/destaque e feedback de comandos após o resultado real. Navegar não chama o callback do controle. |
| 3. Theme Studio | Botão Fechar editor; remoção do tab temporário, retorno à aba anterior e scopes limpos. Catálogo/tema preservados no fechamento normal. Edições não salvas oferecem salvar/descartar/cancelar; falha de escrita mantém a view aberta. Reabertura sem duplicação. |
| 4. Script Hub | Modalidade opcional integrada à mesma janela, virtualização, flags, perfis e runtime. Cadastro dinâmico de jogos/scripts, pesquisa, imagens, fallback, favoritos, ordenação, metadados, Play por entrada, estado vazio, exclusão mútua, cancelamento e teleporte explícito. |
| 5. APIs | CreateScriptHub na Library/Window; CRUD de jogos/scripts, pesquisa, seleção, favoritos, status/Play, miniaturas/retry, TeleportToGame e lifecycle do hub. CloseThemeStudio, studio:Close/IsDirty. Assinaturas e limites em SCRIPT-HUB.md e API.md. |
| 6. Auto Game Detection | Seleciona PlaceId exato primeiro; depois UniverseId = game.GameId. Sem correspondência não cria entradas fictícias. AutoDetectGame pode ser desligado. Não executa callbacks nem teleporte. |
| 7. Carregamento remoto | Distribuição principal por HTTP/loadstring. Loader verifica capacidades, conteúdo, compilação, inicialização, APIs e versão. Nenhum arquivo local ou ModuleScript é obrigatório; readfile/writefile continuam opcionais para perfis. |
| 8. Raw verificado | [Raw 1.9.0 confirmado](https://raw.githubusercontent.com/ManoGustavo0/RetroBox/b5ce7707762b878188840881f28cff9a300b50b5/RetroBox-UI-v1.1.0/retrobox-ui/RetroBox.lua). O conteúdo foi baixado e comparado byte a byte à fonte testada; o exemplo do prompt inicializou essa fonte no simulador sem funções de arquivo do executor. |
| 9. Versão do artefato | RetroBox.lua declara `Library.Version = "1.9.0"` e retorna a Library com CreateWindow e CreateScriptHub. |
| 10. Testes | 221 testes de lógica, 19 exemplos, loader sem capacidades de arquivo, eventos de clique/toque/teclado simulados, catálogo/flags/imagens/actions/teleporte simulados, validator do prompt, fonte remota e integridade do pacote. 221/221 aprovados e 19 exemplos carregados/limpos; o validator e o exemplo do prompt com a fonte publicada passaram. |
| 11. Limitações | Renderização, clipping, métricas de fonte, input, assets e teleporte reais permanecem pendentes. APIs legadas de teleporte cliente podem ser rejeitadas. TeleportAsync exige servidor; adapter da experiência é opcional. Callbacks devem cooperar com cancelamento. Pool máximo 64, cache 128, quatro requests de imagem, 512 jogos/4096 scripts. |
| 12. Arquivos | RetroBox.lua, Loader.lua, testes de navegação/hub/distribuição e runner; exemplos script-hub/remote-loader; guias, READMEs, CHANGELOG, validator e visuais regenerados para a versão. 28 arquivos alterados/adicionados; os 114 arquivos publicados são comparados ao pacote. |
| 13. Documentação | API, THEMES, ADVANCED, RUNTIME, INTEGRATION, GITHUB, VALIDATION, SCRIPT-HUB, DISTRIBUTION e Prompt-RetroBox-IA atualizados. O prompt completo mantém temas, ícones, controles, estados, tarefas, ações, perfis, gráficos e exemplos. |
| 14. Commits/publicação | Código publicado no commit b5ce7707762b878188840881f28cff9a300b50b5, branch codex/script-hub-v1.9.0, repositório ManoGustavo0/RetroBox. Commit adicional atualiza este relatório com os resultados verificados; PR para main. O prompt usa o raw confirmado da implementação, disponível antes do merge. |

O contrato permanente está em [DISTRIBUTION.md](DISTRIBUTION.md); a API nova em [SCRIPT-HUB.md](SCRIPT-HUB.md); o teste nativo pendente em [VALIDATION.md](VALIDATION.md). Os dados do exemplo são demonstrativos, exceto os identificadores de sessão realmente fornecidos pelo cliente. Nenhuma entrada vazia é tratada como destino real.
